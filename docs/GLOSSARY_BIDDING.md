## 1. 가격이 정해지는 순서

공공입찰에서 낙찰 판정 기준이 되는 가격은 **개찰 순간에 추첨으로 결정된다.** 이 순서를 모르면 아래 지표가 전부 오해된다.

| 순서 | 용어 | 뜻 |
|---|---|---|
| ① | **기초금액** | 발주기관이 공고에 제시하는 기준 금액. 모든 계산의 출발점 (API `presmptPrce`) |
| ② | **복수예비가격**(복수예가) | 기초금액 ±2~3% 범위로 만든 **15개** 후보 가격 (API `totPrdprcNum`) |
| ③ | **예정가격** | 입찰자들이 뽑은 번호로 선택된 **4개** 예비가격의 평균 (API `drwtPrdprcNum`) |
| ④ | **낙찰하한선** | 예정가격 × 낙찰하한율. **이 밑으로 쓰면 무효** |

⚠️ **예정가격은 개찰 전에 알 수 없다.** 추첨이기 때문이다. 그래서 BidEasy는 **낙찰가를 예측하지 않는다** — 대신 "얼마 밑으로 쓰면 무효인가"를 지킨다.

- **사정률** = 예정가격 ÷ 기초금액. 보통 97~103% 사이에서 움직인다.
- **투찰률** = 우리 투찰가 ÷ 기초금액 (%).
- **낙찰하한율** = 예정가격 대비 최소 투찰 비율. 공사·금액대·시행일별로 다르다(예: 10억 미만 공사 89.745%). 공고가 직접 명시하기도 한다(API `sucsfbidLwltRate`).
- **A값** = 국민연금·건강보험·산재보험·고용보험·노인장기요양 등 **법정 고정비 합계**. 투찰가 공식에서 사정률을 적용하지 않고 그대로 더한다.
  `투찰가 = (예정가격 − A값) × 투찰률 + A값`
  ⚠️ 실측상 공고의 99.99%에서 A값이 결측이라, 현재 모의투찰은 A값 0으로 계산한다(한계).

## 2. 낙찰자 결정 방식

| 용어 | 뜻 |
|---|---|
| **적격심사제** | 최저가 순으로 이행능력(실적·재무·기술)을 심사해 통과한 첫 업체가 낙찰. **BidEasy 비치헤드** |
| **소액수의견적** | 소액 공사에서 2인 이상 견적을 받아 결정. 건수는 가장 많음 |
| **제한적최저가** | 낙찰하한율 이상 중 최저가 |
| **협상에의한계약** | 가격이 아니라 제안 내용으로 겨룸 → **모의투찰 대상 아님** |

## 3. 판정 — 우리 투찰가가 어떻게 되는가

세 가지 결과만 있다. 판정 정의는 자가보정(`optimizer.simulate_params`)과 **동일하게** 고정돼 있다.

| 판정 | 조건 | 의미 |
|---|---|---|
| **무효**(DROPOUT) | 투찰가 < 낙찰하한선 | **입찰 자체가 없던 일이 된다.** 가장 나쁜 결과 |
| **적중**(WIN) | 낙찰하한선 ≤ 투찰가 ≤ 실제 낙찰가 | 하한선을 통과하면서 낙찰자보다 낮았다 |
| **밀림**(LOST) | 투찰가 > 실제 낙찰가 | 유효하지만 더 싼 업체에 밀렸다 |

- **무효율** = 무효 ÷ 판정된 건. **1차 지표.** 브랜드 KPI가 유효율이라 이걸 먼저 본다.
- **적중률** = 적중 ÷ 판정된 건. **내부 참고용.** ⛔ 대외에 "낙찰률"로 표기하는 것은 금지(전역 규칙 §4-2) — 개별 건은 추첨이 섞인 확률 게임이라 약속이 될 수 없다.
- ⚠️ **적중이 곧 1순위 낙찰은 아니다.** "낙찰자보다 낮은 유효가"라는 뜻이고, 우리보다 낮은 제3자가 있었을 수 있다. 순위·동가추첨은 모델링하지 않는다.

## 4. 실험 용어

| 용어 | 뜻 |
|---|---|
| **arm** | 동시에 시험하는 전략 하나. A/B 테스트의 각 안. 모의투찰은 5 arm 을 같은 공고에 동시 등록한다 |
| **사전 등록**(pre-registration) | 결과를 보기 **전에** 가격·지표·판정 기준을 확정해 잠그는 것. 사후에 유리하게 고치는 것(체리피킹)을 구조적으로 막는다 |
| **백테스트** | 과거 데이터에 전략을 적용해 사후 재구성하는 것. 빠르지만 파라미터가 바뀌면 **과거 수치도 함께 변한다** |
| **holdout** | 파라미터 학습에 쓰지 않고 남겨둔 검증용 데이터. 과적합 여부를 본다 |
| **과적합** | 학습 데이터에만 잘 맞고 새 데이터에서 무너지는 것 |
| **Wilson 신뢰구간** | 비율의 불확실성 범위(95%). 표본이 작으면 넓어진다. 폭이 겹치면 우열을 단정할 수 없다 |
| **오라클**(oracle) | 사후에 최적값을 골랐을 때의 상한. **어떤 알고리즘도 넘을 수 없는 천장** |
| **무효율 캡** | 최적화 시 "무효율이 이 값을 넘지 않는다"는 제약. `frontier_c5` = 캡 5% |
| **프론티어** | 캡을 바꿔가며 얻은 "안전↔적중" 최적 곡선 |

### 5 arm 구성

| arm | 정의 | 성격 |
|---|---|---|
| `standard` | 기초금액 × 97.5% | 슬라이더 기본값 — 실사용자 다수의 실제 행동 |
| `active` | 현 자가보정 전략 | 운영 정본 |
| `frontier_c5` | 무효율 캡 5% 최적 | 안전 우선 |
| `frontier_c10` | 무효율 캡 10% 최적 | 균형 |
| `aggressive` | 기초금액 × 88% | 시장 추격 가설 |

## 5. 게이트 — 언제 무엇을 판정하는가

`docs/MOCK_BIDDING_DESIGN.md` §0.4 에서 **구현 착수 전에 동결**한 기준이다.

| 게이트 | 조건 | 통과하면 |
|---|---|---|
| **G-A** | 등록분의 채점 도달률 ≥ 60% | 지표를 해석할 자격이 생긴다. **미달이면 다른 숫자를 보지 않는다** |
| **G-B** | 적격심사제 400건 누적 + `active` 가 `standard` 를 유의하게 상회 | "우리 추천이 기본값보다 낫다"를 우리 데이터로 말할 수 있다 |
| **G-C** | `frontier_c10` 이 `active` 를 유의하게 상회 + 무효율 ≤ 11% | Pro+ "전략 투찰" 제품화 **검토** 착수 |

**킬 기준**도 함께 등록돼 있다 — 8주 후에도 G-A 미달이면 기능 중단, 6개월간 어떤 arm 도 `standard` 를 못 이기면 알고리즘 우위 주장을 접는다.

## 6. 오답노트 태그

채점에서 실패한 건에 붙는 사유. **태그별 무효율이 곧 사용자 경고 기능의 근거**가 된다.

| 태그 | 뜻 |
|---|---|
| `A값_결측` | 공고에서 A값을 못 구해 0으로 계산 (실측 99.99%) |
| `하한율_테이블폴백` | 공고가 하한율을 명시하지 않아 금액대 테이블로 추정 |
| `기초금액_정정` | 변경공고 — 등록 시점 스냅샷과 실제가 다를 수 있음 |
| `기초금액_변경됨` | 등록 후 실제로 기초금액이 바뀐 것이 확인됨 |
| `예가_비표준` | 복수예가가 15/4가 아닌 건 (실측 11.2%) |
| `사정률_극단` | 예정가격이 기초금액 대비 상·하위 극단으로 튄 건 |
| `재공고건` | 이전 공고가 유찰돼 다시 올라온 건 |
| `예정가격_결측` | 개찰결과에 예정가격이 없어 기초금액으로 근사 |
