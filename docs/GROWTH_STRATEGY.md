## 0. 결론 먼저

1. **지금 병목은 제품이 아니라 배관(plumbing)이다.** 제품은 3-Tier로 완성돼 있고, 콘텐츠 생산 설비(Phase 0~3)·리드 마그넷·귀속 추적까지 다 지어놨다. 그런데 **검색엔진이 들어올 문이 56개뿐이고**(§1.1), **밖으로 나가는 메시지 채널이 0개다**(§1.2). 새 기능을 짓는 것보다 이 두 개를 뚫는 게 압도적으로 싸고 크다.
2. **최대 유입 레버 = 개찰결과 아카이브(프로그래매틱 SEO).** 우리가 매일 쌓는 `OpeningResult`(누가·얼마에·몇 대 1로 落)는 **검색 수요가 확실하고, 만료되지 않고, 경쟁사가 로그인 뒤에 숨겨둔** 데이터다. 이걸 공개 SSR 페이지로 만들면 공고 수만큼의 상록 랜딩이 생긴다. 데이터 해자를 유통 자산으로 환전하는 유일한 수단.
3. **최대 전환 레버 = 아웃바운드 채널(SES + 알림톡).** 지금 체험 만료 리마인드·마감 리마인드·추천공고·리드 육성이 **전부 인앱 알림**이다 → 안 들어온 사람에겐 도달률 0. 체험 14일짜리 상품에서 D-3에 말을 못 거는 건 전환 설계의 구멍이다. 외부 승인 리드타임(도메인 인증·템플릿 심사)이 있으므로 **오늘 신청**이 정답.
4. **가장 싼 유료 유입 창이 열려 있는데 안 쓰고 있다.** 도구 키워드 파워링크 광고 0건(`AD_CAMPAIGN_VALIDATION.md` SERP 정찰). 2주 14만원 예산·패키지 완성 상태로 3주째 보류 중. CPC 바닥 구간은 경쟁사가 들어오면 닫힌다.
5. **원칙은 안 바꾼다.** 낙찰률·예측 마케팅 금지, 비치헤드(전문건설·전기공사 1~10인) 집중, 가격 인하 금지. 이 문서의 모든 유입은 **"안전(무효·적자 회피)"과 "자격(넣을 수 있나)"** 두 훅으로만 들어온다.

## 1. 진단 — 코드·라이브 실측으로 확인한 구조적 사실

### 1.1 검색엔진이 들어올 문이 56개다 (유입 병목 ①)

```
sitemap.xml 실측(2026-07-27): 총 61 URL
  /bid/*  50  ← backend/app/api/v1/endpoints/pages.py:132 `.limit(50)`
  /blog/* 5 + 목록 1
  정적    5
```

- `SEO_CHECKLIST.md`에는 "진행중 공고 최대 5,000건이 자동 노출됨"이라 적혀 있으나 **코드는 50건이다.** 문서-코드 불일치이며, 2026-06 SEO 1층 작업의 기대 효과가 처음부터 1/100로 걸려 있었다.
- **크롤 경로도 막혀 있다**: `/search`는 정적 셸 + `fetch('/bids/feed')`(`infra/nginx/html/search.html:132`) → 라이브 HTML에 공고 링크가 **한 줄도 없다**. 즉 사이트맵 50건 외에 봇이 `/bid/*`에 도달할 내부 링크 경로가 사실상 없다.
- `/bid/*`는 SSR 품질 자체는 괜찮다(canonical·OG·`GovernmentService` JSON-LD·기초금액 노출 확인).
- **만료 처리 부재**: 마감 90일 후 공고 삭제(`notice_crawl_tasks.py:23 PURGE_AFTER_DAYS=90`) → 색인된 URL이 404로 변한다. 410도 아니고, 대체 페이지로의 canonical도 없다. 색인 자산이 새는 구조.

### 1.2 밖으로 나가는 채널이 0개다 (전환 병목 ①)

- `backend/app/tasks/` 전체에 SMTP·SES·boto3·알림톡 어댑터가 **없다.** `trial.send_expiry_reminders`·`deadline.send_reminders`·`recommend.send_matches`는 전부 인앱 `Notification` 행 생성이다.
- 결과: **14일 체험자에게 D-3·D-1에 말을 걸 방법이 없다.** 이탈자는 영구 이탈.
- `Lead` 캡처는 라이브인데(`/leads/capture`) 육성 발송은 미구축 → **"알려드릴게요"라고 받은 연락처에 아직 아무것도 못 보낸다.** 신뢰 리스크이자 낭비.

### 1.3 생산 설비 대비 산출이 낮다 (유입 병목 ②)

- 콘텐츠 엔진은 Phase 0~3 완비 + 정본 모델 Claude Sonnet 5 + 채널 파생(`derive_channel_assets`) + 예약 발행까지 지어놨다. 스케줄도 주 2편 가능(월 데이터스토리 + 수 지식글).
- **그런데 라이브 블로그 글은 5편이다.** 설비 가동률이 낮다. 주제 큐 24개는 주 1편이면 24주치 — 확장 없이는 반년 뒤 소진.
- 5편 중 4편이 2026-06 SEO 1층 작업물, K1 1편이 신규 엔진 산출. 즉 **엔진은 아직 1편밖에 안 뽑았다.**

### 1.4 이미 만들어둔 유입 자산이 미가동

| 자산 | 상태 | 비고 |
|---|---|---|
| 네이버 검색광고 패키지 | 완성·보류(2026-07-05~) | 예산 승인됨(2주 14만원), 경쟁 파워링크 0건 |
| 무료 자격 진단(`/diagnose`) | 라이브 | 랜딩 hero 링크 1곳 외 유입구 없음 |
| 크롬 웹스토어 listing | 가격 문구 구버전(24,900) | 스토어 검색 = 고의도 무료 채널인데 방치 |
| 익스텐션 오버레이 진단 CTA | 설계만 | 재제출 묶음 대기 |
| `derive_channel_assets`(릴스·카드·네이버) | 코드 라이브 | 실제 업로드된 채널 계정 운영 흔적 없음 |

### 1.5 전환 계측이 클릭에서 끊긴다 (전환 병목 ②)

- GA4 이벤트는 `cta_*`·`calc_demo_use`·`lead_*` 등 **클릭 단계까지만** 있다. 가입 이후 "제품을 실제로 써서 가치를 봤는가"(활성화)를 나타내는 이벤트가 없다.
- 특히 PR #28로 **프로필 미기재 = UNKNOWN(판정 불가)**가 됐다 → 면허·지역을 안 채운 계정은 제품 핵심 가치(자격 판정)가 아예 안 뜬다. **프로필 완성률이 전환의 선행지표인데 계측·유도 장치가 없다.**

## 2. 성장 방정식과 북극성 지표

```
유료 매출 = 방문 × 무가입가치사용률 × (리드캡처 | 가입) × 프로필완성률 × 활성화율 × 체험→결제율 × 유지율
```

- **북극성 지표(NSM)**: **주간 활성 투찰자(WAB)** = 최근 7일 내 *투찰 안전 판정(계산기/자격/AI 중 1회 이상)*을 실제로 수행한 계정 수.
  - 이유: 매출의 선행이면서, 우리 약속("잃지 않게")의 실사용을 직접 센다. **낙찰률 계열 지표는 전역 금지**(CLAUDE.md 함정목록 2) — WAB은 그 규칙과 정합.
- **보조 지표 3개**: ① 오가닉 세션(검색) ② 리드→가입 전환율 ③ 체험→결제 전환율.
- **금지**: 노출수·팔로워·글 편수 같은 허영 지표를 성과로 보고하지 않는다. 편수는 투입이지 성과가 아니다.

### T1. 사이트맵·색인 위생 수리 — ✅ **구현 완료(2026-07-27, 배포 대기)**
1. `pages.py` 사이트맵 **인덱스 구조**로 전환: `/sitemap.xml`(인덱스) → `/sitemap-static.xml`·`/sitemap-blog.xml`·`/sitemap-notice-{n}.xml`(각 5,000 URL 상한, 표준 준수).
2. 진행중 공고 **전량** 포함(`.limit(50)` 제거, 페이지네이션으로 대체). `lastmod` 부여.
3. **만료 공고 처리 정책 확정**: 마감 후에도 페이지를 살리되 상단에 "마감된 공고" 배지 + 개찰결과 링크. 삭제 대상은 `410 Gone` 반환(404 아님) → 봇이 색인에서 빨리 뺀다.
4. `/search`에 **SSR 초기 결과 50건 + 링크** 주입(JS는 그대로 갱신). 크롤 경로 개통. *(CLAUDE.md §2 "공개 페이지 SPA 금지" 원칙에 부합하도록 되돌리는 작업)*
5. 서치콘솔·네이버 서치어드바이저에 새 사이트맵 재제출 + 색인 커버리지 주 1회 확인.

> **킬 기준 없음** — 이건 실험이 아니라 버그 수리다.

**구현 결과(2026-07-27)**
- `/sitemap.xml` → **sitemap 인덱스**. 하위 `/sitemap-static.xml`·`/sitemap-blog.xml`·`/sitemap-notices-{N}.xml`(5,000건/파일, `SITEMAP_CHUNK`). **50건 상한 제거 → 진행중 공고 전량.**
- `lastmod`: 블로그만 부여. 공고는 **의도적으로 미부여** — 신뢰할 수 있는 수정시각이 없고 수집시각은 lastmod 가 아니다(기존 세션의 결정 유지).
- `/search`를 백엔드 SSR 로 전환. 서버가 마감임박순 40건을 `/bid/{no}` 링크로 렌더 → 크롤 경로 개통. JS 는 기존대로 최신 피드로 교체(UX 무변경). 정적 `search.html` 제거, `/search.html` → 301.
- `/bid/{없는 공고}`: 200+noindex(soft-404) → **404**. 마감된 공고는 살려두되 "마감된 공고" 배지 + 검색 링크(색인 유지).
- 테스트 422건 통과(신규 SEO 회귀 14건 포함).
**후속(2026-07-27) — IndexNow 색인 통보 추가**
- 구글 sitemap ping 은 폐지(현재 404)라 자동 재제출 경로가 없다. robots.txt 선언이 있어 재제출은 가속용일 뿐 필수가 아니며, 서치콘솔 클릭은 사람 몫으로 남는다.
- 네이버는 **IndexNow**(2023-07~, 서치어드바이저 로그인 불요)로 자동화했다. 블로그 발행·일일 공고 수집 시 신규 URL 을 네이버·Bing 에 즉시 통보한다. 사이트맵이 "언젠가 보라"라면 IndexNow 는 "지금 생겼다"를 직접 알리는 것 — 주 2편 발행 + 일 900건대 공고 갱신 구조에서 상시 효과가 난다.
- 상세·안전장치: `docs/SEO_CHECKLIST.md` §C-2. **통보이지 색인 보장이 아니다** — 판정은 서치어드바이저 수집 현황으로 2주 뒤.

- ⚠️ **배포 필수 조건**: nginx conf 변경 포함(`= /search`·`~ ^/sitemap-…`·`= /search.html` 301) → `./deploy.sh deploy` 가 `nginx -t` 통과 시 자동 reload. 배포 후 서치콘솔·서치어드바이저에 사이트맵 **재제출**(인덱스 구조로 바뀌어 재크롤 필요).

### T2. 개찰결과 아카이브 — **최대 레버**
- **무엇**: `/result/{bid_no}` SSR 페이지 — 공고명·발주기관·기초금액·예정가격·**낙찰업체·낙찰가·낙찰률·참여업체 수**. 하단에 "이 조건이면 내 안전 투찰 밴드는?" → `/calculator` 프리필 CTA, "이런 공고 자격 되나?" → `/diagnose` CTA.
- **왜 이게 1등 레버인가**:
  - 검색 의도가 **명시적 상업 의도**다("○○ 낙찰 결과", "○○ 낙찰가", "예정가격 얼마"). 검색한 사람 = 투찰자 본인.
  - **상록(evergreen)**: 공고는 마감되면 죽지만 개찰결과는 안 죽는다. 색인 자산이 누적된다.
  - **데이터 해자를 유통으로 환전**: 자가보정 플라이휠이 도는 한 페이지 수가 매일 는다. 경쟁사가 베끼려면 데이터부터 모아야 함.
  - 정직 포지션과 정합: 과거 사실만 보여줄 뿐 예측이 아니다.
- **구현 메모**: `OpeningResult`는 이미 `organization`·`region`·`winner_*`·`participants_count`를 갖고 인덱스도 있다(`models.py:183`). 템플릿은 `bid_detail.html` 패턴 재사용. JSON-LD는 `Dataset` 또는 `GovernmentService` + `FAQPage`.
- **주의(정직 가드)**: 낙찰업체명은 공공데이터 공개 정보지만, **"이 업체를 이기려면" 같은 프레이밍 금지**(경쟁 조장·정보 오용). 표기는 사실 나열 + 자사 안전 도구 연결까지.
- **킬 기준**: 배포 8주 후 서치콘솔에서 `/result/*` 오가닉 클릭이 주 20 미만이면 T6(카테고리 허브)로 예산 이전.

### T4. 네이버 검색광고 — 즉시 집행
- `AD_CAMPAIGN_VALIDATION.md` 패키지 그대로, **단 랜딩만 수정**: 소재 A(안전) → `/calculator`, 소재 B(자격필터) → **`/diagnose`**(현재 둘 다 계산기). 훅과 랜딩이 일치해야 A/B가 훅 검증이 된다.
- 2주 집행 후 판정: 소재별 CTR = pain 순위 / 소재별 가입·리드 전환 = 훅 깊이(`/admin/stats/attribution` utm_content).
- **킬 기준**: 2주 후 리드 CPA가 20,000원(≒Pro 1개월) 초과이고 개선 여지 없으면 유료 유입 중단, 오가닉·콘텐츠에 집중.

### T5. 콘텐츠 엔진 가동률
- 주 2편(월 데이터스토리 + 수 지식글)을 **실제로** 돌린다. 검수 게이트가 병목이면 "검수 대기 알림"을 어드민에 띄운다.
- 주제 큐: `GET /admin/blog/topics/propose`(PR #34)로 **월 1회 8개 보충**을 루틴화. 소진 경보는 이미 있음.
- **주제 선정 기준을 검색 수요로 바꾼다**: 서치콘솔 "노출은 되는데 순위 낮은 쿼리" → 그 쿼리 전용 글. 큐를 감으로 채우지 않는다.
- 네이버 이원화: 본문 canonical은 자사, 네이버 블로그는 요약형 + 원문 링크(중복 색인 회피).

### T6. 카테고리·지역 허브
- `/notices/{공종}/{지역}`(예: `/notices/전기공사/서울`) SSR 목록 + 해당 조건 설명(하한율·자격 요건 요약). 진행중 공고 + 최근 개찰결과를 함께 링크 → T1·T2로 크롤 흐름 분배.
- 비치헤드 우선: 전기공사 × 17개 시·도 = 17페이지부터. 전 조합 자동생성은 **금지**(얇은 페이지 대량 생성 = 스팸 판정 위험).

## 9. 미검증 전제 (정직)

1. **개찰결과 검색 수요의 크기를 모른다.** "낙찰 결과/낙찰가" 계열 키워드 검색량은 네이버 키워드 도구로 **먼저 확인**해야 한다(T2 착수 전 30분 작업). 수요가 미미하면 T2는 T6 뒤로 내린다.
2. **현재 오가닉 트래픽 절대값을 모른다.** 증감률 기준 목표는 Week 0 스냅샷 이후에만 확정 가능.
3. **체험→결제 전환율의 현재값을 모른다.** C3의 기대 효과는 "도달 0 → 도달 가능"이라는 구조 개선까지만 확실하고, 개선 폭은 추정이다.
4. **알림톡 템플릿 승인 여부·기간은 통제 불가.** 반려 시 SES 단독으로 시퀀스를 먼저 돌린다.
5. **경쟁사 대응.** 광고 선반이 비어 있는 상태는 영구적이지 않다.
