> 작성 2026-07-27 · 상태: **신청 대기(사용자 작업)** · 코드는 승인 후 착수
> 배경: `GROWTH_STRATEGY.md` §1.2 — 현재 체험 만료·마감·추천·리드 육성이 **전부 인앱 알림**이라 안 들어온 사람에겐 도달률 0. 14일 체험 상품에서 D-3에 말을 못 거는 건 전환 설계의 구멍이다.

## 0. 왜 두 채널인가 (그리고 무엇을 어디로 보내는가)

두 채널은 대체재가 아니라 **법적으로 쓸 수 있는 범위가 다르다.** 이걸 처음부터 나눠 설계해야 템플릿 반려·스팸 신고를 피한다.

| 메시지 | 성격 | 채널 | 근거 |
|---|---|---|---|
| 관심공고 마감 임박(D-3/D-1) | **정보성** | 알림톡 | 사용자가 직접 담아둔 공고의 상태 알림 |
| 자격 매칭 신규 공고 알림(신청자) | **정보성** | 알림톡 | 사용자가 신청한 서비스의 이행 |
| 체험 만료 안내 + 결제 유도 | **광고성 소지 큼** | 이메일(SES) | 구독 전환 유도 = 영리 목적 |
| 윈백 할인 안내 | **광고성** | 이메일(SES) | 사전 수신동의 + (광고) 표기 필요 |
| 리드 육성(비회원 진단자) | **광고성 소지** | 이메일(SES) | 회원이 아닌 대상에 대한 서비스 권유 |

**원칙**: 알림톡은 *사용자가 명시적으로 신청·설정한 것*만. 결제 유도·할인·권유는 전부 이메일. 이 선을 넘으면 템플릿이 반려되고, 반복되면 **발신프로필 자체가 차단**된다.

## 0-1. 진행 현황 (2026-07-27 갱신)

| 단계 | 상태 |
|---|---|
| DNS: SPF (`v=spf1 include:_spf.google.com include:amazonses.com ~all`) | ✅ 등록·확인 |
| DNS: DMARC (`p=none`, rua=hosicompany@gmail.com) | ✅ 등록·확인 |
| SES 도메인 자격증명 `bideasy.kr` (서울 ap-northeast-2) | ✅ 생성 |
| DNS: DKIM CNAME 3개 | ✅ 등록·권위 NS 확인 |
| SES 도메인 인증 | ✅ **Verified** (DKIM SUCCESS) |
| SES 프로덕션 액세스 | ⏳ **심사 중**(PENDING) — 승인 전까지 일 200통·인증 주소만 |
| 발송용 IAM 키(앱) | ⬜ 승인 후 |
| 카카오톡 채널 / 중계사 / 템플릿 | ⬜ 미착수 |

**도메인 DNS 는 카페24**(`ns1.cafe24.com`)에서 관리한다. API 가 없어 레코드 추가는 수동이다.

⚠️ **와일드카드 주의**: `*.bideasy.kr → bideasy.kr` 와일드카드 CNAME 이 존재한다. 명시적으로 등록한 레코드가 우선하므로 DKIM 은 정상 동작하지만, **레코드를 지우면 조용히 와일드카드 응답으로 되돌아가** 인증이 깨진 걸 눈치채기 어렵다. DKIM CNAME 3개는 삭제 금지.

⚠️ **SPF 는 도메인당 1개만** — 나중에 다른 발송 서비스를 붙일 때 새 TXT 를 추가하지 말고 기존 줄에 `include:` 를 덧붙일 것(2개면 permerror).

## 1. AWS SES (이메일) — 먼저 시작할 것

리드타임이 길고 우리 쪽 작업이 대부분이라 먼저 건다.

### 1-1. 도메인 인증 (30분 + DNS 전파)
1. AWS 콘솔 → **Amazon SES** → 리전 **아시아 태평양(서울) ap-northeast-2** 선택
2. **Identities → Create identity → Domain** → `bideasy.kr`
3. **Easy DKIM** 선택(RSA_2048 기본) → SES 가 **CNAME 3개**를 준다
4. 그 CNAME 3개를 `bideasy.kr` DNS 에 등록 (도메인 등록기관/Cloudflare 등 현재 쓰는 곳)
5. 상태가 **Verified** 로 바뀔 때까지 대기(보통 수십 분, 최대 72시간)
6. 함께 권장: **SPF**(`v=spf1 include:amazonses.com ~all`) · **DMARC**(`v=DMARC1; p=none; rua=mailto:...`) TXT 레코드

> 도메인 인증이 끝난 뒤 프로덕션 액세스를 요청하면 승인이 빠르다(AWS 문서상 모범 사례).

### 1-2. 프로덕션 액세스 요청 (샌드박스 해제)
샌드박스 상태에서는 **인증된 주소로만** 발송 가능 + 일 200통 제한이라 실서비스에 못 쓴다.

SES → **Account dashboard → Request production access**. 심사 질문에 답할 내용을 미리 준비:

| 질문 | BidEasy 답변 초안 |
|---|---|
| 메일 유형 | Transactional (전체 발송량의 다수가 거래/서비스 알림일 때. 결제 유도·윈백 등 마케팅 메일이 다수라면 Marketing 선택) |
| 웹사이트 URL | `https://bideasy.kr` |
| 사용 사례 | 공공입찰 분석 SaaS. 가입자에게 구독 상태·체험 만료·마감 임박·맞춤 공고 알림을 발송 |
| 수신자 확보 방법 | 자사 서비스에서 해당 이메일 수신을 명시적으로 요청·동의한 가입자와 무료 진단자만. 구매 목록·크롤링 수집 없음 |
| 반송/불만 처리 | SES 이벤트(bounce·complaint)를 구독해 자동 수신거부 처리, 모든 메일에 opt-out 링크 |
| 수신거부 방법 | 메일 하단 1클릭 수신거부(서명 토큰, 로그인 불요) |

AWS 는 **24시간 내 초기 응답**을 목표로 하지만, 추가 정보가 필요하면 더 오래 걸릴 수 있다. 반려되면 사용 사례를 더 구체적으로 적어 재요청.

> ⚠️ **발송 전 차단 조건 — 현재 동의 증적이 없다.** `/diagnose` 는 연락처 사용 목적을 안내하지만, 광고성 이메일에 대한 별도 명시 동의와 그 증적(`consented_at`·동의 문구 버전·동의 채널)을 저장하지 않는다. 따라서 **기존 진단 리드에게 체험 전환·윈백·서비스 권유 메일을 자동 발송하면 안 된다.** 발송 코드보다 먼저 미선택 기본값의 동의 UI와 철회·증적 저장을 구현하고, 동의하지 않은 리드는 자동 육성 대상에서 제외한다.

### 1-3. 신청 후 (우리 코드 작업 — 승인 나면 착수)
- `services/nurture.py` + `ses_mailer.py` 어댑터 (결제 PG 다중화와 동일한 pluggable 패턴)
- bounce/complaint 웹훅 → `Lead.nurture_status` / 사용자 수신설정 자동 반영
- 수신거부 링크(서명 토큰) 엔드포인트
- 체험 시퀀스 6통(D0/D1/D3/D7/D11/D13) — `GROWTH_STRATEGY.md` §C3

**필요한 환경변수**(승인 후 서버 `.env.production`): `AWS_SES_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`(SES 전용 IAM 사용자, 권한은 `ses:SendEmail`·`ses:SendRawEmail` 만), `MAIL_FROM=no-reply@bideasy.kr`

## 2. 카카오 알림톡 — 중계사 계약이 먼저

**카카오와 직접 계약하는 게 아니다.** 알림톡은 카카오와 파트너 계약된 **공식 딜러사(중계사)**를 통해서만 발송할 수 있다. 우리가 고를 것은 "어느 중계사를 쓸 것인가"다.

### 2-1. 준비물
- **카카오톡 채널** 개설(비즈니스 채널) — 없으면 먼저 만든다. 채널 검색용 아이디 필요
- 사업자등록증
- 채널 관리자 권한 계정

### 2-2. 중계사 선택 → 발신프로필 등록
1. 중계사 가입(솔라피/알리고/비즈엠/NHN 등 — 발송단가·API 품질·잔액 관리 방식으로 비교)
2. **발신프로필** 등록 = 우리 카카오톡 채널을 알림톡 발신 주체로 연결(채널 관리자 인증 필요)
3. 발송 단가는 중계사마다 다르므로 **계약 전 확인**. 실패 시 SMS 대체발송(LMS) 단가도 함께 확인

### 2-2-1. ⚠️ 계획상 2~3주를 잡는다 (초판 오기 정정 2026-07-27)

초판은 "+3~5일"로 적었으나 이는 **템플릿 심사만** 본 수치였다. 알림톡은 관문이 셋이며, 중계사·서류 보완 여부에 따라 달라지므로 아래는 보수적 일정이다:

| 단계 | 소요 |
|---|---|
| 일반 채널 개설 | 즉시 |
| **비즈니스 채널 전환**(사업자 인증) | 3~5일 — 알림톡은 비즈니스 채널만 가능 |
| **발신프로필 등록·심사** | 영업일 최대 10일 |
| 템플릿 심사 | 카카오 기준 영업일 2일 이내(중계사 반영 여유를 포함해 2~3일 계획) |

**결론: SES(24시간 내 초기 응답 목표)와 알림톡(계획상 2~3주)의 리드타임 차이가 크다.** 체험 시퀀스·리드 육성은 **전부 이메일로 먼저 완성**하고, 알림톡은 나중에 마감·매칭 알림에 얹는다. 알림톡을 기다리며 전환 개선을 미루지 않는다. 다만 대기 시계를 일찍 돌리기 위해 **채널 신청은 지금** 건다.

### 2-3. 템플릿 심사 (카카오 기준 영업일 2일 이내, 반려 시 재심사)
정보통신망법 + 카카오 내부 기준으로 심사한다. **광고성 문구가 들어가면 반려**된다.

우리가 올릴 템플릿(정보성만):

| 템플릿 | 용도 | 주의 |
|---|---|---|
| `deadline_reminder` | 관심공고 마감 D-3/D-1 | 사용자가 담아둔 공고임을 본문에 명시 |
| `match_new_notice` | 신청한 조건의 신규 공고 알림 | "신청하신 조건" 문구로 정보성 근거를 남긴다 |
| `welcome_diagnose` | 무료 진단 결과 안내 | 결과 요약만. 가입·결제 권유 문구 금지 |

**반려를 부르는 표현(넣지 말 것)**: 할인·특가·이벤트·지금 구독하세요·무료체험 시작하기·이모지 남발·과장 문구. 링크는 자사 도메인만.
**우리 도메인 규칙과의 정합**: 낙찰률·적중률 암시 문구는 전역 금지(CLAUDE.md 함정목록 2) — 템플릿에도 동일 적용.

> 반려는 이상한 일이 아니다. 여유 있게 **3~4종을 동시에** 올리고, 반려 사유를 반영해 재제출한다.

### 2-4. 신청 후 (우리 코드 작업)
- `kakao_alimtalk.py` 어댑터 (중계사 API 규격에 맞춰) + 실패 시 SMS 대체발송 정책 결정
- `Lead.nurture_channel` 이 이미 `kakao|email` 을 갖고 있으므로 행 단위 채널 분기는 스키마 변경 없이 가능

## 3. 법적 필수 (둘 다 해당)

- **광고성 정보**는 사전 수신동의와 매체별 표시 의무를 지킨다. 이메일은 제목 시작에 **(광고)**를 표시하고 본문에 전송자 정보·수신거부 방법을 둔다. 기본 알림톡은 정보성 메시지만 보내며 광고를 섞지 않는다.
- **야간(21:00~08:00) 광고성 전송**은 별도의 야간 수신동의가 필요하다. 단, 시행령상 **전자우편은 야간 별도 동의의 예외**다. 그래도 신뢰·운영 일관성을 위해 체험 만료·윈백 메일은 주간 발송으로 고정한다.
- 수신거부·동의 철회는 **무료로, 지체 없이** 반영하고 그 처리 결과를 **수신자에게 알려야 한다**.
- 명시 동의는 나중에 입증할 수 있어야 한다. 동의 시각·대상 채널·동의 문구 버전과 철회 시각을 저장한다.
- 진단 리드 연락처는 수집 시 고지한 목적(공고 알림·서비스 안내) 밖으로 쓰지 않는다.

## 4. 진행 순서 (권장)

```
완료          SES 도메인·DKIM 인증
현재          SES 프로덕션 심사 대기 ─────────┐
              카카오톡 채널 확인/개설 ─────────┤ 병렬
              중계사 선택·가입 ────────────────┘
+3~5일 계획   카카오 비즈니스 채널 승인 → 중계사 발신프로필 등록
+2~3주 계획   발신프로필 심사 → 템플릿 심사 → 알림톡 가동
SES 승인 즉시 동의 증적 UI/DB → services/nurture.py + ses_mailer → 동의한 대상부터 체험 시퀀스 가동
```

**먼저 오는 승인부터 붙인다.** SES 가 먼저 나면 체험 시퀀스(이메일)부터 돌리고, 알림톡은 나중에 마감/매칭 알림에 얹는다. 둘을 기다렸다가 한 번에 하지 않는다.

## 5. 지금 못 하는 것 (정직)

- **발송 인프라 없이 캡처된 리드**는 계속 쌓이는데 접촉이 안 된다. 볼륨이 작은 지금은 수동 접촉이 유효하지만, 리드가 늘면 약속 불이행이 된다 → 그래서 신청이 급하다.
- **기존 진단 리드는 광고성 메일 수신동의 증적이 없다.** 새 동의 UI를 배포한 뒤 동의한 대상부터 자동 육성을 시작하고, 기존 리드를 소급 동의 처리하지 않는다.
- 이 문서는 신청 절차이고, **효과(전환율 개선)는 시퀀스 가동 후 4주 데이터로만 판정**한다. 킬 기준은 `GROWTH_STRATEGY.md` §7.
