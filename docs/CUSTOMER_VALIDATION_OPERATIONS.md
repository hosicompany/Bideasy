# 고객 메시지 검증 운영표

> 상태: 배포·외부 모집 전 검수 중
> 기간: 목표 표본 확보일부터 최대 21일
> 정본: `docs/AD_CAMPAIGN_VALIDATION.md`

## 1. 운영 원칙

- 전화·대면·화상 인터뷰 없이 비보조 온라인 테스트만 한다.
- 운영진 승인을 받은 커뮤니티와 기존 수신 동의 관계에만 모집 링크를 제공한다.
- 공개 사업자 명단의 연락처를 광고 발송에 전용하지 않는다.
- 링크 문구에서 A/B를 미리 나누지 않는다. 서버가 같은 모집 코호트 안에서 균형 배정한다.
- 한 참가자는 브라우저 토큰으로 한 메시지에 고정하며 다른 안을 보여주지 않는다.
- 이름·업체명·이메일·전화번호를 받지 않는다. 자유서술에 개인정보를 적지 말라고 안내한다.
- 10명씩의 결과로 통계적 승자를 선언하지 않는다.

## 2. 모집 준비

운영 환경에는 다음을 설정한다.

```text
MESSAGE_TEST_ENABLED=true
MESSAGE_TEST_ACCESS_KEYS=<코호트마다 생성한 충분히 긴 무작위 키>
MESSAGE_TEST_IMAGE_PATH=/guide-assets/<승인된 전기공사 화면>.png
MESSAGE_TEST_IMAGE_CAPTION=공개 G2B 화면 · 공고번호 <번호> · <YYYY-MM-DD> 기준
```

접근 키는 비밀 관리 시스템에 저장하고 Git·운영표·스크린샷에 남기지 않는다. 채널마다 다른 키를
써서 서버가 해시 코호트를 만들게 한다. 모집을 끝내면 해당 키를 설정에서 제거한다.
화면은 타깃에 맞는 실제 공개 전기공사 공고와 BidEasy 패널이어야 하며 계정·회사·개인정보를 먼저
마스킹한다. 이미지 경로와 출처·공고번호·기준일 캡션이 모두 없으면 서버가 테스트 배정을 503으로
막는다. 네 값을 모두 검수한 뒤에만 `MESSAGE_TEST_ENABLED=true`로 바꾼다.

모집 링크 형식:

```text
https://bideasy.kr/message-test?key=<승인된 접근 키>
```

`message-test.html`은 `noindex`이며 sitemap에 포함하지 않는다.

## 3. 자동 선별·배정

참가자가 직접 다음을 답한다.

| 항목 | 포함 조건 |
|---|---|
| 업종 | 전기·전기공사·전문공사·전문건설 |
| 직원 수 | 1~10명 |
| 직접 입찰 담당 | 예 |
| 월 공고 검토 | 10건 이상 |

조건을 만족하면 서버가 코호트별 A/B 수를 비교해 적은 쪽으로 배정하며, 같으면 무작위로 정한다.
부적격 응답은 메시지를 노출하지 않는다.

## 4. 이해도 결과 기록

개인 단위 원문은 관리자 인증이 필요한 API에서만 확인한다. 일일 운영표에는 집계만 남긴다.

| 날짜 | 모집 코호트 | 적격 배정 A/B | 제출 A/B | A 이해 3+ | B 이해 3+ | A/B 신뢰 중앙값 | 예측 오해 A/B | 판정 |
|---|---|---|---|---|---|---|---|---|
| YYYY-MM-DD | 채널 별칭 | 0/0 | 0/0 | 0 | 0 | -/- | 0/0 | 수집 중 |

사전등록 판정:

- 안별 제출 10명 미만: `collect_more`
- A만 통과: `advance_a`
- B만 통과: `advance_b`
- 둘 다 통과: `advance_both`
- 둘 다 탈락: `rewrite_and_retest`

## 5. Creative 제작·검수

1. `/admin-creatives`에서 통과 메시지의 brief를 만든다.
2. 실제 화면 입력 파일의 계정·회사·개인정보 마스킹을 확인한다.
3. brief를 승인하고 큐에 넣는다.
4. 인증된 운영자 Mac에서 로컬 runner를 시작한다.
5. 생성 원본 뒤에 결정적 UI·카피·대표 음성을 합성한다.
6. Virality 보고서와 실제 UI 픽셀 보존 여부를 검수한다.
7. 사람이 승인한 대표 자산만 게시 상태로 전환한다.

인증 만료는 `AUTH_REQUIRED`, 원본·카피 변경은 `STALE`, 사람 반려는
`CHANGES_REQUESTED`로 처리한다. 이전 결과물을 덮어쓰지 않고 새 attempt를 만든다.

## 6. 행동 검증 기록

`/api/v1/admin/growth/creative-funnel`의 `creative_id`별 집계를 사용한다.

| 날짜 | creative_id | 안 | 타깃 방문 | 무료 가치 | 설치 클릭 | 실제 공고 활성화 | 28일 반복 | 판정 |
|---|---|---|---:|---:|---:|---:|---:|---|
| YYYY-MM-DD | UUID | A/B | 0 | 0 | 0 | 0 | 0 | 수집 중 |

메시지별 타깃 방문 20건 또는 21일 중 먼저 도달한 때 판정한다. 활성화 2건 미만이면 승자를 선언하지
않는다. 같은 사용자·같은 공고 중복을 빼고, 서로 다른 공고를 서로 다른 날짜에 확인했을 때만 반복
사용자로 센다.

## 7. 개인정보·보상·중단

- 자유서술에 개인 식별정보가 들어오면 결과 공유본에서 삭제한다.
- 테스트 참여 보상은 총 10만원 이내에서 이해도 응답 완료에만 지급한다.
- 설치·활성화·후기에는 보상을 지급하지 않는다.
- 수신 동의 철회 또는 게시물 삭제 요청은 즉시 반영한다.
- 비정상 반복 제출, 접근 키 유출, 귀속 손실이 보이면 모집을 중단하고 원인을 먼저 고친다.
