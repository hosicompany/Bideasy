# BidEasy 온라인 메시지·크리에이티브 검증

> 상태: **기능 구현 완료, 배포·외부 모집 전 검수 중** (2026-08-14)
> 목적: 조회수나 클릭률이 아니라 `실제 공고 확인`까지 이어지는 메시지를 찾는다.
> 운영 경계: 전화·대면 인터뷰, 공개 사업자 명단 콜드 발송, 무단 커뮤니티 홍보를 하지 않는다.

## 1. 고객·경쟁·제품 결론

- 고객: 전기·전문공사 1~10인 업체에서 월 10건 이상 공고를 직접 검토하는 대표·입찰담당자.
- 경쟁: AI 요약·자격·가격 기능은 빠르게 평준화되고 있다. 실제 주 경쟁은
  `나라장터 + 공고문 + 엑셀` 수작업이다.
- 제품: BidEasy가 가장 분명하게 소유할 수 있는 차이는 **나라장터 공고 옆에서 작동하는
  Chrome 사이드패널**이다.

문제의 실재성은 공개 공고에서 확인됐지만, 문구가 실제 고객에게 이해되고 행동을 만드는지는
아직 증명되지 않았다. 따라서 아래 두 단계를 통과하기 전 광고 예산을 확대하지 않는다.

## 2. 메시지 정본

브랜드 엔드라인은 `투찰 전 마지막 확인, BidEasy.`로 유지한다. 첫 검증은 다음 두 안만 비교한다.

| 안 | 헤드라인 | 검증할 가설 |
|---|---|---|
| A | `나라장터 공고 옆에서, 자격·A값·하한선을 한 번에.` | 제품 메커니즘과 사용 장면이 이해되는가 |
| B | `이 공고, 우리 회사가 진짜 넣어도 될까요?` | 자격 불안이 더 강한 첫 행동을 만드는가 |

공통 요소는 바꾸지 않는다.

- 설명: `보고 있는 공고 화면에서 참가조건·계산 기준·주의 조항을 확인하세요. 낙찰가는 예측하지 않습니다.`
- CTA: `이 공고 확인하기`
- 엔드라인: `투찰 전 마지막 확인, BidEasy.`
- 화면: 같은 실제 공개 G2B 공고와 같은 BidEasy 사이드패널 화면

`공고는 더 많이, 투찰은 더 정확하게.`는 성과 또는 투찰가 정확도 암시로 읽힐 수 있어 실사용
증거가 생기기 전까지 사용하지 않는다.

## 3. 1단계 — 비보조 5초 이해도 게이트

`/message-test`는 운영진 승인을 받은 커뮤니티 게시물과 기존 동의 관계에서 전달한 접근 키로만
연다. 서버는 접근 키 원문을 저장하지 않고 해시 코호트로 바꾸며, 같은 코호트 안에서 A/B 수를
맞춘다. 한 참가자는 브라우저 토큰으로 한 메시지에 고정된다.

### 사전 선별

- 전기·전문공사
- 직원 1~10명
- 입찰을 직접 담당
- 월 공고 검토 10건 이상

적격 참가자에게 같은 실제 화면과 배정 문구를 5초 보여준 뒤 자동으로 가린다. 이후 다음 세 문항을
자유서술로 받는다.

1. 무슨 서비스라고 이해했는가
2. 언제 사용하는가
3. 무엇을 확인해준다고 이해했는가

신뢰도와 업무 관련성은 각각 5점 척도로 기록한다. 이름·업체명·전화번호·이메일은 받지 않는다.

### 사전 코딩과 통과선

자유서술에서 다음 네 항목을 코드화한다.

- 나라장터 또는 공공입찰
- 투찰 전
- 자격·A값·하한선 중 하나 이상
- 공고 옆 또는 한 화면

각 안은 다음을 모두 만족해야 통과한다.

- 제출 완료 10명 이상
- 10명 중 7명 이상이 네 항목 중 세 개 이상을 자발적으로 언급
- 신뢰도 중앙값 4 이상
- `낙찰가를 예측한다`는 오해가 2명 미만

판정은 통계적 승자 선언이 아니라 탈락·진출 게이트다. 한 안만 통과하면 해당 안만 진출하고, 둘 다
통과하면 둘 다 진출한다. 둘 다 탈락하면
`투찰 전, 자격·A값·하한선을 한 화면에서 검산.`으로 다시 작성해 새 코호트에서 재검증한다.

관리자는 `/api/v1/admin/message-validation/summary`에서 표본, 코드 적중, 신뢰도 중앙값, 예측 오해와
사전등록 판정을 확인한다.

## 4. 2단계 — Higgsfield 15초 행동 검증

통과안은 같은 본편·대표 실제 음성·CTA를 유지하고 첫 2초 헤드라인만 바꾼다.

| 구간 | 화면·음성 |
|---|---|
| 0~2초 | A 또는 B 헤드라인 |
| 2~5초 | 실제 나라장터 화면 옆에 BidEasy 패널 등장 |
| 5~10초 | 자격·A값·하한선의 실제 결과 확대 |
| 10~13초 | `낙찰가는 예측하지 않습니다. 확인 가능한 기준부터 보여드립니다.` |
| 13~15초 | 엔드라인과 `이 공고 확인하기` |

얼굴·AI 아바타·TTS를 쓰지 않는다. 공고번호·기관·기준일은 표시하되 계정·회사·개인정보는
Higgsfield 업로드 전에 가린다. 실제 UI·한글·금액·공고번호는 생성 모델이 다시 그리지 않으며,
원본 화면을 결정적으로 합성한다.

### 제작 경로

- 이미지 배경: `gpt_image_2` 또는 `marketing_studio_image`
- 15초 모션: `marketing_studio_video`, `specific_mode=from_storyboard`, 9:16, 1080p,
  `generate_audio=false`
- 실제 화면 비율 변환: `reframe`
- 완성 MP4 사전 검수: `brain_activity`
- CLI: `1.1.23` 고정, 인증된 운영자 Mac의 로컬 runner에서만 실행

Virality Predictor는 훅 최고점 3초 이내, sustain 70% 이상, 주의 집중이 제품 장면과 겹치는지만
검수한다. 기준 미달은 수정 요청으로 돌리되 운영자가 사유를 남겨 예외 승인할 수 있다. 점수는 실제
활성화 성과를 대체하지 않는다.

### 2026-08-15 음성 전 준비 상태

프리프로덕션 정본은 [`CREATIVE_PREPRODUCTION_15S.json`](./CREATIVE_PREPRODUCTION_15S.json), 사람 검수
절차는 [`CREATIVE_PREPRODUCTION_15S.md`](./CREATIVE_PREPRODUCTION_15S.md)에 고정했다. 공개 전기공사 사례는
`R26BK01488342-000`이며, credits를 쓰지 않는 로컬 렌더로 A/B 보드와 15초 무음 AAC 프리비즈를 만들었다.

- A/B는 0~2초 훅만 다르고 2~15초 프레임은 동일하게 검증한다.
- provider storyboard에는 한글·로고·실제 UI·공고번호·금액을 넣지 않는다.
- 기존 guide 화면 다섯 장은 의미상 부적합해 브랜드 manifest에서 `campaign_approved=false`로 막는다.
- 새 마스킹 전기공사 화면과 대표 실제 음성이 모두 비공개 입력 경로에 올라오기 전에는 queue하지 않는다.
- runner는 UI를 `0~2초 숨김 → 2~5초 등장 → 5~13초 결과 확대 → 13~15초 숨김`으로 결정적 합성한다.
- 이 단계에서는 Higgsfield 유료 생성, Virality Predictor, 게시를 실행하지 않는다.

## 5. 행동 퍼널과 귀속

단일 판정 퍼널은 다음과 같다.

```text
qualified_visit
→ free_value_completed
→ chrome_install_clicked
→ notice_check_completed
```

- 웹 계산·진단은 무료 가치로만 집계한다.
- 핵심 활성화는 로그인 사용자에게 실제 공고 context 응답에서 발급한 120초·1회용 receipt와
  canonical `bid_no`가 함께 검증될 때만 기록한다. receipt는 위조·재생·다른 공고 귀속을 막지만,
  일반 Chrome Extension에는 서버측 attestation이 없으므로 raw HTTP가 Extension Origin을 흉내 내는
  것까지 증명하지는 못한다. 따라서 이 값은 제품 보안 경계가 아니라 캠페인 방향성 지표로 사용한다.
- 같은 사용자·같은 공고 새로고침은 한 번만 센다.
- 서로 다른 공고를 서로 다른 날짜에 확인해야 반복 사용자로 센다.
- `utm_content`와 UUID `creative_id`는 익명 방문, 리드, 가입, 실제 공고 확인까지 유지한다. 실제 공고
  귀속은 서버가 가입 시 승인 상태를 검증해 저장한 first-touch만 사용하고 Extension body 값은 무시한다.
- `/go/{creative_id}`는 승인된 크리에이티브의 허용된 내부 랜딩으로만 이동한다.

행동 검증은 메시지별 타깃 방문 20건 또는 21일 중 먼저 충족되는 시점에 판정한다. 실제 공고
활성화가 2건 이상이면서 비교안의 2배 이상일 때만 잠정 승자로 부른다. 활성화가 2건 미만이면 승자를
선언하지 않고 A안을 기본값으로 유지한다. 조회수·CTR·Virality 점수만으로 선정하지 않는다.

## 6. 채널·예산

### 우선순위

1. 실제 공고 기반 자체 콘텐츠와 계산·확인 유틸리티 SEO
2. 주 2개 짧은 화면 데모와 주 1개 실제 공고 사례 재가공
3. Chrome Web Store 설명·실제 UI·소개 영상 최적화
4. 허가형 커뮤니티 또는 기존 동의 관계의 링크 모집
5. 네이버 검색은 메시지 A/B가 아닌 최대 2만원 고의도 smoke test

검색량 실측상 `낙찰하한율계산`, `적격심사계산` 같은 기능어 표본이 작아 검색광고를 메시지 A/B의
주축으로 쓰지 않는다. 검색량 부족은 메시지 실패로 판정하지 않는다.

### 월 30만원 기본 배분

- 타깃 온라인 테스트 참여 보상: 최대 10만원
- 실제 화면 편집·대표 음성·자막: 10만원
- 네이버 고의도 smoke test: 최대 2만원
- 제작 도구·Higgsfield 추가 사용 대비: 8만원

보상은 이해도 테스트 참여에만 지급한다. 설치·활성화·Chrome 리뷰에는 보상을 지급하지 않는다.
누적 활성화 5명과 반복 사용자 2명 전에는 광고비를 늘리지 않는다.

## 7. 90일 목표

- 타깃 활성 사용자 10명
- 28일 내 반복 사용자 4명
- 메시지별 실제 활성화 귀속 가능
- 사람 검수를 통과한 Higgsfield 크리에이티브 12개 이상
- 추가 광고비 판단에 쓸 최초 활성화 경로 확보

외부 커뮤니티 게시, 광고 생성·충전·활성화, 사용자 메시지 발송은 코드 배포와 별개의 승인 작업이다.
이 문서는 그 작업을 자동 승인하지 않는다.

## 8. 금지선

- `낙찰 보장`, `적중률`, `100% 자격 판정`, `실격 방지`, `무효·적자 0`
- 근거 없는 시간 절감·투찰량 증가·수주 증가 주장
- 가짜 후기, 보상성 설치·리뷰
- 조달청·나라장터 공식 또는 제휴 서비스로 보이는 표현
- 공개 사업자 디렉터리 대상 자동 메시지 발송
