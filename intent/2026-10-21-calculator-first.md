# 계산기 중심 사이트로 전환 — 의도 문서

상태: **논의중** (2026-10-21 초안)
근거: [`docs/data/ga4/2026-10-21.md`](../docs/data/ga4/2026-10-21.md) (GA4 28·90일 + 네이버 서치어드바이저 30일)

## 1. 한 줄 의도

**사람들은 "숫자 하나·공식 하나"를 찾아 네이버에서 들어온다. 사이트의 첫 화면을 그 질문에 바로 답하는 계산기로 바꾸고, 몇 달간 쌓은 데이터(공고·개찰·기초금액·A값)를 계산기 옆의 '참고값'으로 공개한다.** 유료 전환 퍼널은 접지 않되 뒤로 보낸다.

## 3. 설계 변경 아이디어 (우선순위순)

### A. 첫 화면 = 계산기 (S)
- `/` 히어로를 지금 `/calculator` 의 입력 3개(계약종류·기초금액·투찰률[·A값])가 **바로 동작하는** 폼으로 교체. 로그인·설명 없음. 제품 소개·요금제는 그 아래로.
- `/calculator` 는 그대로 둔다(색인·CTR 자산). `/` 는 "계산기 + 소개", `/calculator` 는 "계산기 전용" — 중복 아님.
- `calculator.html`(28일 16회) → `/calculator` 로 301. 같은 내용이 두 URL 로 색인되는 중.

### B. 검색어에 답하는 정적 페이지 2개 (S) — "데이터 자산" 첫 공개
- **`/lower-limits` 낙찰하한율표**: `lower_limits.py` 의 금액대별 티어(89.745 / 88.745 / 87.495 …)를 표 하나로. 검색어 1위 `87.745` 와 `낙찰하한선 미달 뜻` 이 여기 떨어진다. 정본은 코드이므로 SSR 또는 빌드 시 생성(수기 복사 금지 — 요율 개정 때 갈라진다).
- **`/a-value` A값이란**: 블로그 A값 가이드가 이미 CTR 6.4% 로 잘 됨 → 글은 두고, **실측 A값 분포**(보유 3,604건, 금액대별 중앙값)를 표로 덧붙인다. 계산기 기본값 `12,400,000` 하드코딩을 이 중앙값으로 교체.

### D. 제목 수정 (S, 즉시)
- K11 → 검색어 `낙찰하한율 계산하는법` 포함 제목. 투찰가 계산 글 → `투찰금액 계산기` 포함. **slug·URL 은 그대로, `<title>`·H1 만**. 2주 뒤 서치어드바이저 CTR 로 판정.

### E. 로그인 벽 걷기 (S)
- 계산·조회·공고 상세는 비로그인 전부. 로그인은 저장(관심공고·마감추적)·알림·AI 분석만. `bid.html` 의 "로그인이 필요해요" 분기 재점검.

### F. 수익 (나중)
- 광고: 계산 결과 **아래** 배너 1슬롯만, 월 5만 조회 뒤 실험. 결과를 막는 전면·보상형 ✕.
- 제휴(보증보험·인증서·면허)가 방문자당 수익이 더 클 가능성 — 광고보다 먼저 검토.

### G. 모의투찰 공개 성적표 — "엔진이 돌고 있다"를 숫자로 (M) · 2026-10-21 추가
- **의도**: 매주 월 21:00 이미 생성되는 `mock_bid.weekly_report`(관리자 전용)를 공개 SSR 페이지 `/track-record` 로 낸다. 기존 등록·채점·게이트 로직은 손대지 않고 **읽기 전용 화면만 추가**한다. 계산기 결과 아래에 한 줄("이 로직으로 지난주 N건 모의투찰 · 하한선 미달 0건 →")로 연결한다.
- **보여도 되는 것** (설계 정본 §0.2·§0.6 준수):
  | 항목 | 표기 | 근거 |
  |---|---|---|
  | 주간 등록·채점 공고 수, 누적 | "지난주 등록 312건 · 채점 완료 168건 · 누적 2,1xx건" | 운영 투명성, 게이트 무관 |
  | **무효율 → 유효율** (1차 지표) | "하한선 미달 0건 — 유효율 100%" (arm 별) | 브랜드 KPI. 전역 규칙 §4 |
  | 사정률 예측 오차 (4차 지표) | "예정가격 사정률 예측 오차 중앙값 0.xx%p" | "우리 모델의 순수 신호" |
  | 표본 품질·게이트 진행률 | "적격심사 유효 표본 91/400 — 판정 전" 진행 막대 | 미달 상태를 숨기지 않는 것이 신뢰 |

- **왜 '몇 % 됐다'가 아니라 '무효 0건'인가**: 적중률은 추첨 노이즈가 커서 주마다 흔들리고(과적합 8%→23% 전력), 올라가면 예측 서비스처럼 읽혀 "낙찰가 예측 안 함" 포지션과 충돌한다. 유효율·오차는 매주 안정적으로 나오고 우리 주장과 일치한다.
- **배치 변경(기능 유지)**: 상단 메뉴 = 계산기 · 하한율표 · 공고검색 · 개찰결과 · **모의투찰 성적표** · 블로그. 로그인 도구(관심공고·마감추적·대시보드·비교·근거서)는 "내 작업" 메뉴 하나로 묶는다. 기존 URL·API·태스크 변경 0.

## 4. 검색 노출 보존 규칙 (개편 중 깨지면 안 되는 것)

1. **URL 불변 목록** — 아래는 slug 를 바꾸지 않는다: `/`, `/calculator`, `/blog/nakchal-hahanyul-guide`, `/blog/a-value-guide`, `/blog/knowledge-k11`, `/blog/tuchalga-calculation`, `/bid/*`, `/search`, `/blog`, `sitemap*.xml`.
2. 옮기는 URL 은 **301 + 새 URL 을 canonical** (`calculator.html` → `/calculator`). 404·410 은 없는 페이지에만.
3. 제목을 고칠 때 **H1·title·description 만**. 본문 첫 문단의 핵심 수치(89.745% 등)는 유지 — 네이버가 그 숫자로 매칭하고 있다(`87.745` 검색어).
4. SSR 유지. 새 페이지(`/lower-limits`, `/result/*`)도 SSR + canonical + JSON-LD. JS 로만 그리는 페이지 금지.
5. 개편 배포 직후: 사이트맵 재제출 + IndexNow(이미 자동) + 서치어드바이저 "수집 요청".
6. **측정**: 배포 전 `docs/data/ga4/` 스냅샷 1장, 2주·4주 뒤 재측정. 상위 5 URL 의 클릭이 20% 이상 빠지면 그 변경만 되돌린다.
7. 검수 게이트(`content_review.py`) 금칙어는 새 페이지 카피에도 적용 — '낙찰률'·'예측' 표현 금지.

- **손익분기**: 고정비 4.5만원 = 월 조회 7,500~22,500. 기본 시나리오로 10~12개월, 낙관이면 6개월.
- **비교 — 구독**: 지금 계산기 사용자 60명/월 중 1%만 Pro(19,900원)로 가도 월 1.2만원 = 보수 시나리오 12개월 광고 수입과 같다. 현재 전환 0 이므로 추정일 뿐이지만, 광고와 구독은 배타적이지 않다 — 둘 다 "계산기를 쓰는 사람 수"에서 나온다.
- **비용이 느는 지점**: 조회 5만/월 넘으면 Lightsail 8GB($44)·Cloudflare 캐시 필요 가능. 그 전까지 운영비는 평평하다.
- **킬 기준**: 6개월 뒤(2027-04) 조회가 보수 시나리오(1,300) 아래면 광고 모델은 접고 제휴·구독에만 집중한다.

## 10. 트래픽 패키지 — 1~4순위를 한 묶음으로 (2026-10-21 사용자 결정)

홈 개편(v2 미리보기)은 **보류**. 같은 목표(검색에서 찾을 때 반드시 나오고, 나온 숫자가 퍼지게)인 아래 넷을 한 패키지로 간다. 각 항목은 **미리보기 → 승인 → 구현** 순서([[preview-before-implement]]).

| # | 항목 | 산출물(URL) | 데이터 원천 | 검색 보존 |
|---|---|---|---|---|
| 1 | 검색어 1:1 페이지 | `/lower-limits`(하한율표) · `/a-value`(실측 A값 분포) · 글 제목 2편 교체(K11·투찰가 계산, slug 불변) | `lower_limits.py` 티어 · `Notice.a_value` 3,604건 중앙값 | 신규 URL 추가만, 기존 변경 0 |
| 2 | 프로그래매틱 페이지 | `/result/{bid_no}` 개찰결과(낙찰자·낙찰금액·낙찰자 투찰률·참가자 수) + `sitemap-results-*.xml` · 기존 `/bid/*` 에 "개찰결과 보기" 링크 | `OpeningResult` · `opening_participants` · `opening_stats` 분위수 | 상록 URL, 410 없음. '낙찰률' 단어 금지 |
| 3 | 공유되는 산출물 | 계산기 공유 링크 `/calculator?basic=&tcl=&a=&ct=` + og:image 에 숫자 렌더 · 투찰 근거서 PDF 하단 `bideasy.kr/calculator` 워터마크 | 기존 `/calculator`·`/rationale` | 기존 URL 그대로, 파라미터만 |
| 4 | 임베드 위젯 | `/embed/calculator`(iframe 전용 경량 페이지) + 계산기 페이지에 "내 블로그에 붙이기" 코드 복사 버튼 | `/calculator` 로직 재사용 | 임베드 페이지는 `noindex` + canonical→`/calculator`(중복 색인 방지) |

**공통 규칙**: SSR · 각 페이지 `<title>` 에 실제 유입 검색어 포함 · 검수 금칙어(`낙찰률`·`예측`) 적용 · 배포 후 IndexNow + 서치어드바이저 수집 요청 · 2주 뒤 `docs/data/ga4/` 스냅샷으로 판정.

**순서 제안**: ①(반나절) → ③(1일) → ④(반나절) → ②(2~3일, 별도 미리보기). 홈 개편은 ②까지 끝나고 유입이 늘어난 뒤 다시 본다.
